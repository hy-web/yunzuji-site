# 常见问题

## 关于产品

### 云族纪和普通族谱软件有什么区别？

普通族谱软件画的是一棵父系树，表达不了"一个人嫁入另一个家族、同时在两边都有身份"这类真实关系。云族纪记录的是一张**关系网**：以父系谱系为骨架，用[分身体系](../guide/architecture#数据模型一个人为什么有三种-id)挂接配偶和外亲，还能自动推算任意两人之间的[称呼](../guide/kinship-engine)，并支持多段婚姻、同族婚姻、跨代配偶等复杂情况。

### 云族纪是免费的吗？

应用本身免费、私有部署。运行所需的 uniCloud 阿里云空间有免费额度，通常足够一个几十到上百人的家族使用；只有规模很大或图片很多时才需要升级付费套餐。

### 为什么是私有部署，而不是做一个大家都能注册的 App？

族谱数据高度隐私，且每个家族是一个天然的小圈子。私有部署让数据只存在家族自己的云空间里，不上架、不开放公网，反而更安全、也更简单——不需要应对公网的注册滥用问题。

### 支持哪些平台？

基于 uni-app，一套代码交付微信小程序、H5 网页和 App。其中微信小程序对长辈最友好（免密登录、扫码即用）。

## 使用相关

### 可以在手机上用吗？

可以。微信小程序、H5、App 都支持，自家人在手机上就能查看和维护族谱。

### 第一个人（始祖）怎么录？

创建家族后，应用会引导你录入始祖。之后通过长按节点，可以向上续接一代、添加子嗣或配偶。第一个注册并建族的账号自动成为家族管理员。

### 为什么有些节点显示成"？"？

显示"？"表示这是一个**匿名节点**——通常是外族半开放视角下的远支骨架，或是本人主动匿名的分身。节点位置和连线还在（保证树的形状完整），但姓名、头像、生卒等个人信息被隐藏了。详见[权限与隐私模型](../guide/permission)。

### 管理员（admin）是干什么的？能有几个？

管理员负责本家族的治理：添加 / 删除未认证成员、设置家族开放档位、管理特批名单、发布家族记录、批量导入数据等。管理员能力在服务端校验，不是前端隐藏按钮那么简单。

### 录错了、删错了怎么办？

几乎所有写操作都有[归档快照](../guide/permission#归档与撤销)：添加、修改、删除、认领、批量导入都能撤销。被删成员短时间内还会以"虚影"留在画布上，可一键恢复。

### 换手机 / 重装后数据还在吗？

数据存在云端（你自己的 uniCloud 空间），不在手机本地。换设备后重新登录同一账号即可看到完整族谱。

## 数据与导入

### 我的数据存在哪里？安全吗？

存在**你自己部署时创建的 uniCloud 云空间**里，不在任何公共服务器上。数据库有权限规则，云函数在服务端做访问校验，外族人默认看不到封闭家族的数据。

### 怎么备份家族数据？

随时可以用「导出 CSV」把全族数据导出成表格保存到本地。建议每隔一段时间备份一次。

### 能导入我以前在别处整理的家谱吗？

可以。按 CSV 模板整理好（含姓名、性别、父母、配偶、祖源地等列），即可批量导入；导入前会先出预览报告，确认无误才写入，且支持整批撤销。

### GEDCOM 是什么？支持到什么程度？

GEDCOM 是家谱软件之间通用的数据交换格式（常见 5.5.1 和新版 7.0）。云族纪可以把 GEDCOM 文件转换成 CSV 后导入，方便从其他家谱工具迁移数据。

### 导入时会重复创建同一个人吗？

服务端有"同一个人"的多维判据（姓名、性别、生日、父母关系等综合判断），并在导入前给出预览和重复提示，避免把一个人录成两条。

## 称呼与关系

### 称呼是怎么自动算出来的？

简单说是四步：先确定你在当前家族的身份，再找你和对方的最近共同祖先、提取代差/父系母系/性别/长幼等特征，然后查一张 200 多条的亲属规则表，最后渲染成带排行的中文称呼。完整原理见[称呼计算引擎](../guide/kinship-engine)。

### 为什么有的关系没显示称呼、只显示名字？

当关键信息缺失（最常见是性别未知）时，系统不会根据位置去猜性别硬凑称呼，而是安全地回落到显示姓名——宁可少叫，也不叫错。补全资料后称呼会自动出现。

### 支持近亲 / 同族 / 跨代婚姻吗？

支持按真实情况记录，系统不强制阻止。这类关系在传统树模型里会报错或画错，正是云族纪用"关系网 + 分身"模型重点解决的场景。

## 技术相关（给开发者）

### 为什么用 uni-app 而不是原生开发？

一套代码同时交付小程序、H5、App，对一个私有部署、用户量不大但要覆盖长辈多端场景的项目，uni-app 的复用率和开发效率最合适。

### 为什么后端用 Serverless 云函数？

私有部署的家族软件没有持续的服务器运维需求，uniCloud 云函数 + 文档数据库免运维、按量计费、免费额度充足，部署者只需点几次上传，不必自己管服务器。

### 族谱听起来像"图"，为什么不用图数据库？

父系血亲本质是严格的树（路径唯一），真正网状的只有配偶 / 外亲这少数挂接点。用约定好的分身结构就能表达，引入图数据库反而增加运维和成本。详见[技术架构](../guide/architecture#为什么不用图数据库)。

### 核心逻辑有测试保障吗？

有。项目包含 50 个 Node 无头回归脚本，覆盖称呼样例、匿名净化、权限裁剪、导入组装等，`node tests/run-all.mjs` 一条命令即可全跑，核心算法改动有自动化兜底。
